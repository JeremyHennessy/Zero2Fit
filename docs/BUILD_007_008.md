# Builds 007–008 — Adventure progression + private progress photos

Baseline: `9358b5e3a64878111b9fb3ead4022a4cfc73afab`.

These builds extend the verified device-driven Zero2Fit application without changing the approved dark/high-contrast/lime visual baseline or the existing workout/data logic.

## Build 007 — RPG auto-adventure

### Non-negotiable progression rule

**Adventure activity never awards Fitness XP.**

Fitness XP remains the real-world progression currency earned from Zero2Fit quests, workouts and verified device activity. RPG battles, enemies, coins, loot and equipment are downstream entertainment systems only.

### Adventure Energy

Adventure Energy is derived from lifetime real-world Fitness XP:

`available charges = floor(lifetime Fitness XP / 25) - previously spent charges`

This means real-world progress powers the game without letting gameplay feed back into the fitness score.

### Expedition loop

The first campaign contains four escalating zones:

1. Foundation Trail
2. Briar Hollow
3. Ironwood Pass
4. Ember Ridge

Later zones require both a minimum real-world Fitness level and victories in the previous zone. Each expedition consumes one Adventure Energy charge and resolves up to three encounters. Enemies have HP, attack and defense values. Bosses enter on a repeatable victory cadence.

The player's combat profile is derived from the existing real-world Strength, Endurance, Consistency, Recovery and Nutrition attributes plus equipped RPG gear. Gear can improve RPG combat but cannot alter Fitness XP or the underlying real-world attribute totals.

### Loot

Victories can award:

- game-only coins;
- weapon loot;
- armor loot;
- charm loot;
- common, uncommon, rare or epic variants.

Loot has a game power value and can be equipped manually or through **Auto-equip best gear**. It has no monetary value and no effect on the fitness data model.

### Auto-adventure

Auto-adventure does not run a hidden browser process. Static GitHub Pages cannot reliably execute after the page is closed.

Instead, Zero2Fit records the last processed time and reconciles elapsed time when the app is opened or focused. The initial cadence is one expedition every two hours, capped at six catch-up runs at a time and further limited by available Adventure Energy.

This keeps the system deterministic, inspectable and compatible with a static GitHub Pages application.

## Build 008 — real progress-photo capture and alignment

### Privacy model

Progress photos are private browser data.

- Raw images are stored as blobs in IndexedDB `progress_photos`.
- A separate `photo_metadata` store keeps non-image metadata.
- JSON backup exports include photo metadata only.
- `raw_photos_included` is explicitly `false`.
- No photo is committed to GitHub.
- No cloud upload is implemented by this build.

Browser-local storage should not be treated as the only permanent backup. Browser/site-data deletion can remove local photos. A later authenticated private-cloud implementation can add durable encrypted/private storage without changing the capture model.

### Capture workflow

For each progress-photo session the user can capture or select:

- Front
- Side
- Back

The module supports:

- user-initiated `getUserMedia` camera access where the browser permits it;
- front/rear camera preference switching;
- photo-library/file selection fallback;
- a fixed head/shoulder/centerline/feet alignment guide;
- zoom adjustment;
- horizontal and vertical alignment offsets;
- previous-photo ghost opacity;
- session coverage status;
- local deletion.

Camera access requires a secure browser context such as GitHub Pages HTTPS and explicit browser permission. The camera is not activated automatically.

### Normalization

Saved photos are rendered locally to a standardized 3:4 frame:

- primary image: 1200 × 1600 JPEG;
- thumbnail: 270 × 360 JPEG.

The selected scale and x/y alignment are baked into the standardized image and preserved as metadata. The most recent prior photo for the same view, excluding the current session, can be shown as a ghost overlay to improve pose consistency.

### IndexedDB schema

Build 008 increments the local IndexedDB schema to version 4 and adds:

`progress_photos`

Indexes:

- `captured_at`
- `view`
- `session_id`

Existing Build 003 stores remain intact.

## Validation

Builds 007–008 add deterministic tests for:

- Adventure Energy derivation;
- zone unlocks;
- seeded deterministic combat;
- the rule that adventure does not mutate Fitness XP;
- gear equip/auto-equip;
- offline catch-up runs;
- photo alignment bounds;
- previous-photo selection;
- front/side/back session coverage;
- photo-session grouping;
- blob stripping from exported metadata.

The existing full Zero2Fit validation and headless-browser smoke tests remain required as regression gates.
